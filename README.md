# BRAIN-POWER · 可溯源 AI 健身搭子

市面上大多数健身产品提供的是最基础的知识，只把助手做成一个记录或排课的道具。而对于已经入门、追求进阶的训练者来说，真正需要的是**根据自己的情况学习知识、建立自己的训练认知体系**。

BRAIN-POWER 是一个懂运动科学的 AI 健身搭子：聊训练、排计划、记你的逐组数据，陪你把训练长期坚持下去。它有三个刻意打磨的地方——

- **建议有迹可循**：每个关键结论都给出真实文献出处（作者 + 年份 + DOI）。出处必须存在于知识库召回原文中，模型编造引用会被代码级护栏拦截打回，而不只是"提示词里求它别编"。
- **方案有针对性**：它先认识你——训练经验、目标、每周可练天数、伤病、场地——再动手排计划。没有档案就不给模板方案。
- **相处有活人感**：它记得你上次说过什么、肩伤有没有好，用你自己的训练数据跟你对账。带情绪时先接人再答事，而不是输出一篇客套话。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 💬 训练知识问答 | 基于运动科学文献库回答增肌、减脂、恢复、补剂等问题，回答附文献出处与适用前提（对新手成立的结论不一定适用你） |
| 📋 针对性计划 | 按你的经验水平、时间、器械、伤病生成周期化计划（如每周 4 天的四周增肌计划），并解释为什么这样排 |
| 🏋️ 逐组记录 | 自然语言打卡，逐组数据落库，不用手动填表 |
| 📈 周期裁决 | 基于完成度、睡眠、酸痛等真实数据，按周期判断该加重、维持还是减载 |
| 🧠 关系记忆 | 长期记住你的偏好、身体反应、生活状态，对话中自然提起 |

## 为什么不做一个普通的"健身 GPT"

直接问大模型健身问题，会遇到两个致命问题：**引用是编的**（模型会自信地给出不存在的文献），**建议是模板**（不知道你的情况，给谁都那一套）。BRAIN-POWER 用工程手段把这两个问题变成"可验证"而非"可祈求"：

1. **引用白名单校验**：回答中每条引用（中文书目、`作者（年份）`、英文 `Author et al., 2017` 等格式）逐条与本次检索召回的原文比对，命中才放行，否则自动打回重答；
2. **精确数字 grounding**：p 值、百分比、效应量这类统计值必须在召回原文中逐字存在，找不到就降级为定性表述；知识库覆盖不到的内容，要求模型明说"这是经验之谈"；
3. **档案先行的对话流程**：信息不足时先提问（一次不超过三个问题），或给出明确标注假设的初稿并追认修正，绝不做无依据的个性化。

## 架构

```
┌─────────────────────────────────────────────────────────────┐
│  移动端 H5（对话 / 计划 / 记录 / 我的）                         │
│  流式渲染 · 工具调用过程可视化 · 打卡弹层                        │
└──────────────────────────┬──────────────────────────────────┘
                           │ SSE
┌──────────────────────────▼──────────────────────────────────┐
│  对话 Agent（解释层）                                          │
│  LLM + 工具调用：rag_search / 计划 / 逐组记录 / 长期记忆         │
│  代码级护栏：引用白名单校验 · 数字 grounding · 违规打回重答        │
├─────────────────────────────────────────────────────────────┤
│  数据层（执行层）                                              │
│  PostgreSQL：训练计划 / 逐组记录 / 每日状态 / 用户档案           │
│  pgvector：文献知识库（~11000 切片）+ 长期记忆                   │
├─────────────────────────────────────────────────────────────┤
│  进化层                                                       │
│  规则引擎按周期数据裁决加重 / 维持 / 减载                        │
└─────────────────────────────────────────────────────────────┘

模型层：OpenAI 兼容 provider 抽象（当前 DeepSeek 主力，DashScope 兜底，
        故障自动降级；换模型只需改一行 .env，不动代码）
```

**知识库**：Springer 运动科学专著与开放获取论文（蛋白质补充 meta 分析、IOC REDs 共识、肌酸立场声明等），PDF 逐页切块入库，引用可溯源到页。文献原文因版权不随仓库分发，clone 后放入自己的文献即可（见 `knowledge/sources/README.md`）。

## 快速开始

```bash
# 1. 数据库（PostgreSQL 16 + pgvector）
docker run -d --name brainpower-pg -p 5433:5432 \
  -e POSTGRES_USER=coach -e POSTGRES_PASSWORD=coach pgvector/pgvector:pg16
docker exec brainpower-pg psql -U coach -c "CREATE DATABASE coach_v2"

# 2. 配置：复制模板并填入你的 API Key
cp .env.example .env

# 3. 文献入库：放入 PDF，并在 scripts/ingest_pdfs.py 的 REGISTRY 登记真实书目信息
python scripts/ingest_pdfs.py

# 4. 启动（打开 http://localhost:8011）
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8011
```

需要 DashScope（Embedding）与 DeepSeek（对话）的 API Key，均为 OpenAI 兼容接口，也可替换为其他兼容端点。

## 项目结构

```
app/
  services/agent.py     Agent 循环 + 引用校验/grounding 护栏（核心）
  services/provider.py  跨厂商模型抽象层
  services/rag.py       PDF 切块 · Embedding · 向量召回
  services/tools.py     工具 schema：检索 / 计划 / 记录 / 记忆
  prompts/              系统提示词（按版本管理，附变更记录）
static/index.html       移动端 H5（单文件，四页签）
scripts/                文献入库 / 稳定性测试 / 评测脚本
eval/                   22 题测评集与稳定性测试结果
docs/                   产品需求文档
```

## 已知边界

- 知识库覆盖以训练科学、运动生理、营养补剂为主，库外问题会明确标注"经验之谈"而非硬编引用——这是设计行为。
- 非医疗产品：伤病与危险信号（放射痛、夜间痛醒、关节肿胀等）一律劝停练就医，不做诊断。
